# 新建小程序规范（多小程序共享仓库）

本仓库是多小程序 Monorepo：所有小程序共享**同一云环境 + 同一套云托管后端**，
登录逻辑共用（`shared/backend/appAuth.js`），后台按小程序切换（`t_staff_apps` 授权），
业务数据按**表前缀**隔离。新增一个小程序只需三步。

## 三步接入

### 第一步：绑定共享云环境

1. 新小程序与现有小程序**同主体**（个人主体也可，需在微信公众平台确认主体一致）。
2. 云开发控制台 → 环境 `cloud1-d6gddqzrsda16338f` → 更多 → **多小程序共享环境** → 绑定新小程序 AppID。
3. 验证：调用任意 `/api` 接口，云托管注入的 `X-WX-APPID` 应为新 AppID；共享后 `X-WX-OPENID` 可能带 `{AppID}_` 前缀（后端会自动剥离，无需前端处理）。

### 第二步：登记小程序（注册表）

在 `shared/backend/sql/upgrade_009_apps.sql` 的 `t_apps` 插入中追加一行，并在 `shared/backend/apps.js` 的 `BUILTIN_APPS` 中追加内置兜底：

```js
// shared/backend/apps.js
"新应用code": { app_id: "新应用code", app_name: "应用名", wechat_appid: "wxXXXXXXXX", app_status: 1 },
```

> `app_id` 即 `app_code`（小写英文），作为后台切换器标识。数据库 `t_apps` 为权威数据，内置表为兜底。

### 第三步：建前端工程 + 分配后台权限

1. **前端工程**：复制 `apps/miniprogram-kxm/` 作为模板，改 `project.config.json` 的 `appid` / `projectname`，
   以及 `miniprogram/utils/api.js`（共享 `CLOUD_ENV` / `CLOUD_SERVICE` 不变）。
2. **业务表**：新小程序的业务表统一使用该小程序的**专属前缀**（如课小满用 `t_lp_*`），
   在 `shared/backend/tables.js` 的 `TABLE_MAP` 中登记逻辑名 → 物理名，并补 `upgrade_*.sql` 建表脚本。
3. **后台授权**：`系统设置 → 管理员管理 → 小程序权限`，为需要管理该小程序的非 admin 员工勾选授权；
   admin 角色默认拥有全部小程序，无需授权。

## 表前缀约定

| 前缀 | 归属 | 说明 |
|------|------|------|
| `t_` | 系统表（共享） | `t_users / t_staff / t_menus / t_seqs / t_file_uploads / t_apps / t_staff_apps / t_dict_* / t_roles / t_role_menus / t_user_sessions / t_user_events / t_service_monitor / t_api_trace / t_staff_events` |
| `t_lp_` | 课小满业务 | `t_lp_tasks / t_lp_task_assignees / t_lp_task_checkins / t_lp_task_collections / t_lp_task_timeline / t_lp_students / t_lp_subscribe_grants` |

- 业务表**不加 app_id 列**（前缀即归属）；共享系统表保留 `app_id` 列用于后台区分用户/事件来源。
- 后端代码一律写**逻辑表名**（如 `db.from("tasks")`），`db.js` 的 Proxy 自动映射为物理表名。

## 后台多小程序说明

- 顶部「小程序切换器」读取 `/admin/myApps`（admin 全部，其余按 `t_staff_apps`）。
- 切换后前端把 `app` 参数附加到所有请求（GET 用 query、POST 用 body），后端 `requireAppAccess` 校验并注入 `req.appId`。
- 通用 CRUD 引擎（`adminApi.js`）配置 `appField: "app_id"` 的模块（共享系统表）自动按 app 过滤；
  专属业务表靠前缀隔离，无需 appField。

## 课小满（环境内直调）注意

课小满通过 **`wx.cloud.callContainer` 直调云托管**（`X-WX-SERVICE: kxm-service`），无需配置 request 合法域名 / 域名备案：

- 登录/绑定：`/api/lp/login`、`/api/lp/bind`（code2session 换 openid，**运行配置存 `t_apps` 表，后台「小程序配置」维护 `app_secret` / `jwt_secret` / `jwt_expires` / `service_url`**，不用环境变量）。
- **邀请码准入**：每个学生账号 `t_staff.invite_code`（6 位大写）；小程序用户必须先绑定邀请码才能进入；
  后台「管理员管理」可对任意账号生成/作废邀请码（所有账号均可自助生成自己的邀请码，新增账号自动生成），
  作废即锁定该账号名下的小程序访问；绑定关系在「学习管理 → 绑定管理」统一维护。
- 业务接口：`/api/lp/tasks|checkins|collections|dashboard|upload`，操作 `t_lp_*` 表。
- 绑定环境：在云开发控制台把课小满绑定到云环境 `cloud1-d6gddqzrsda16338f`；
  `apps/miniprogram-kxm/miniprogram/utils/api.js` 中 `CLOUD_ENV` / `CLOUD_SERVICE` 已配置。

## tdesign 图标乱码（postinstall patch）

tdesign 图标字体由 `icon.wxss` 的 `@font-face` 加载（`font-family: t`，图标是私有区码点 `\E001` 等）。
`package.json` 的 `postinstall` 钩子会执行 `scripts/patch-iconfont.js`：

- 该脚本**只负责把 `@font-face` 指向 TDesign CDN**（`https://tdesign.gtimg.com/icon/.../t.woff`），解决微信开发者工具禁止本地字体路径的报错。
- **切勿删除 `@font-face`**：删掉后图标没有字体可渲染，会显示成乱码/方块（曾踩坑）。
- 手动改过 `node_modules` / `miniprogram_npm` 下的 `icon.wxss` 后，重新执行 `node scripts/patch-iconfont.js` 即可恢复。

## 部署

云托管共享后端只有一个，代码根目录 `shared/backend/`，改动一次部署对所有小程序生效。
各小程序前端仅在上线时上传各自的小程序包。

## 注意事项

- 前端请求 `X-WX-SERVICE` 必须与云托管服务名一致（当前 `kxm-service`）。
- 新增共享系统表/字段必须同时更新 `init_schema.sql`、`init_data.sql`、`upgrade_*.sql` 与 `tables.js`。
- 改表走 `upgrade_NNN_模块.sql` 增量脚本（规范见 `shared/backend/sql/README.md`），禁止直接改已上线库结构。
