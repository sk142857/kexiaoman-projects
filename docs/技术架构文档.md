系统由**三条链路**构成：

1. **小程序用户链路**：小程序 `wx.cloud.callContainer`（环境内直调）→ 云托管业务路由（LP JWT 鉴权）→ MySQL。
2. **管理后台链路**：后台前端（React，`/admin`）→ 云托管后台路由（JWT 鉴权 + 角色-菜单权限）→ MySQL。
3. **可观测链路**：前端上报耗时 + 服务端 `traceMiddleware` → `api_trace`；`monitor.js` 定时采集 → `service_monitor`。

### 3.2 前端-后端通信（课小满环境内直调）

课小满已绑定云环境，前端通过 **`wx.cloud.callContainer` 直调云托管服务**（`X-WX-SERVICE: kxm-service`），
网关自动注入 `X-WX-OPENID` / `X-WX-APPID`，无需配置 request 合法域名 / 域名备案：

```js
wx.cloud.callContainer({
  config: { env: 'cloud1-d6gddqzrsda16338f' },
  path: '/api/lp/tasks',
  method: 'GET',
  data: {},
  header: { 'X-WX-SERVICE': 'kxm-service', 'X-LP-Token': token },
});
```

业务接口统一过 `lpAuth` JWT 鉴权（每次请求实时复核邀请码状态，作废即锁定）。

统一响应结构：`{ code: 0, msg, data }`
- `code === 0` → 成功，resolve `data`
- 否则 → reject `{ code, msg }`
- 网络异常 → reject `{ code: -1 }`

调用成功后异步上报 `client_cost_ms` 到 `/api/analytics/reportTrace`，与服务端 `server_cost_ms` 关联成完整链路。

### 3.3 用户身份

- 登录：`POST /api/lp/login`（wx.login code → code2session 换 openid，复用 `appAuth` 共享登录，静默注册）。
- 绑定：`POST /api/lp/bind` 输入 6 位大写邀请码绑定学生/家属身份（`lp_invites` → `t_lp_students` / `t_lp_family_members`），绑定后一次性锁定身份。
- 鉴权：`lpAuth` 中间件校验 LP JWT，实时复核邀请码状态。

## 4. 后端架构（云托管）

### 4.1 服务入口（`server.js`）

中间件链（顺序关键）：

1. **后台静态托管**：`/admin` 前缀按 `Accept` 头分流——浏览器导航（`text/html`）走 SPA index.html，axios 数据请求（json）走业务路由；静态未命中回退 SPA（支持前端路由刷新）。
2. **JSON 解析**：GET 跳过，POST 宽松解析（`strict: false`，limit 20mb），解析错误返回明确信息。
3. **健康检查**：`GET /`、`GET /healthz`（探活，无需鉴权）。
4. **后台管理路由**：`/admin`（独立 JWT 鉴权，见 §5.1）。
5. **openid 鉴权**：仅对业务 `/api/*` 生效（`/api/lp/*` 走 LP JWT 除外），读取 `X-WX-OPENID`，缺失返回 401；同时按 `X-WX-APPID` 解析当前小程序（`apps.js`）。
6. **链路追踪**（`traceMiddleware`）：捕获请求耗时，写 `api_trace`（跳过健康检查与上报接口自身）。
7. **课小满路由**：`/api/lp/login`、`/api/lp/bind` 为公开接口；其余 `/api/lp/*` 统一过 `lpAuth`。
8. **业务路由**：`/api/user`、`/api/system`、`/api/analytics`、`/api/storage`。
9. **404 兜底**。

### 4.3 数据库访问（`db.js`）

```js
const cloudbase = require('@cloudbase/js-sdk');
const app = cloudbase.init({ env: process.env.CLOUDBASE_ENV_ID, accessKey });
const db = app.rdb();   // MySQL RDB 实例

// 链式查询（逻辑表名自动映射为物理表名，见 tables.js）
await db.from('tasks')
  .select()
  .match({ task_status: 'doing' })
  .order('created_at', { ascending: false })
  .limit(50);
```

- `countRows(table, col, applyFilters)`：精确行数统计（优先 `count: "exact"`，失败回退拉主键列计数），后台仪表盘等聚合使用，避免拉全量行。
- 主键发放统一走 `seq.js` 的 `nextSeq(seqKey)`（读 `seqs` 表当前值 → 自增 → 写回）。

> ⚠️ **AI-SKIP**：`ws` 依赖是 rdb() 运行时必需（WebSocket 连 MySQL），源码无显式 `require('ws')`，勿删。

### 4.4 错误处理与响应

- 统一 `ok(data, msg)` / `fail(msg, code)` 封装（`response.js`）。
- 业务校验失败 `code=400`；资源不存在 `code=404`；无权访问 `code=403`；系统异常 `code=500`。
- 每个路由 try/catch，异常打印 `console.error` 并返回「服务异常」。

### 4.5 内容审核机制

- 用户提交的**打卡**默认进入 `pending`；`task_checkins` 含 `review_status`（pending/approved/rejected）。
- 未审核通过（pending/rejected）的内容前端**脱敏展示**：正文 `****`，图片由后端正常返回、前端做磨砂 + 锁 ICON；待审核打卡禁止修改（前后端双重校验），可删除。
- 用户**资料审核**：`users` 表 `nickname_pending`/`avatar_pending`/`avatar_hd_pending`/`gender_pending` + `profile_review_status`。
- 后台通过 `/api/users/reviewProfile`、打卡审核接口（`/api/checkin_reviews/*`）处理。

### 4.6 图片上传与缩略图

- **小程序端（课小满）**：图片压缩 → base64 → 逐张直调 `/api/lp/upload`（后端并发上限 3，避开单次请求体过大），后端用 `sharp` 内存压缩后上传 COS。
- **后台端**：学习模块经 `/admin/api/upload`（base64）上传，归属当前登录员工。
- **存储**：COS 桶 `636c-cloud1-d6gddqzrsda16338f-1467751604`，共享根路径 `kxm`，按业务分目录（`tasks/avatar/events`）；公开域名 `https://636c-cloud1-d6gddqzrsda16338f-1467751604.tcb.qcloud.la/{路径}`。
- **缩略图（数据万象）**：展示层统一使用 `?imageMogr2/thumbnail/{size}x{size}` 缩略图避免渲染原图，原图 URL 保留给预览；仅对内部存储域名追加处理参数，外部 URL（微信头像）原样返回。
- **删除**：`storage.js` 提供 `markRemoved`（逻辑删除，审计留痕）、`removeFiles`（物理删除 COS 对象，批量分片 50/次，失败逐条重试）。

## 5. 管理后台架构（cloud admin）

### 5.1 鉴权与登录

- 独立 JWT，不依赖小程序 openid。`staff` 表存储后台账号（`staff_username`/`staff_password`(bcrypt)/`staff_role` admin|student|parent|family/`staff_status`）。
- `adminAuth` 中间件校验 `Authorization: Bearer <token>`，并校验员工仍存在且启用。
- 登录限流：同一 IP+账号 15 分钟内最多 5 次尝试（进程内滑动窗口），登录失败写 `staff_events` 审计。
- JWT 密钥 `ADMIN_JWT_SECRET`（未配置回退内置密钥并告警），有效期 `ADMIN_JWT_EXPIRES`（默认 12h）。

### 5.2 角色-菜单权限

- 菜单存 `menus` 表（分组/叶子树形），角色-菜单关联存 `role_menus`，默认角色 admin/student/parent/family。
- `/admin/menus` 按角色返回菜单树（管理员全部，学生/家长/家属仅学习管理），前端动态渲染 ProLayout。
- `requireModulePermission` 中间件做模块级鉴权：非管理员只能访问其角色已授权菜单对应的模块，越权返回 403；`dict_types`/`dict_items` 的 GET 为共享参考（任意角色可读），写操作统一按「数据字典」菜单鉴权。
- 自愈：`menus/roles/role_menus` 表为空时自动写入默认菜单（`ensureDefaultMenus`），数据字典为空时写入默认字典（`ensureDefaultDicts`）。
- **多小程序支持**：顶部「小程序切换器」按 `t_staff_apps` 授权；管理员默认全部；切换后业务接口按当前小程序过滤（学习模块走 `t_lp_*` 表、共享系统表按 `app_id` 过滤）。

### 5.3 通用 CRUD 引擎（`routes/adminApi.js`）

`crudRouter(opts)` 为业务表生成统一接口（list/detail/create/update/delete），按配置驱动：

| 配置项 | 说明 |
|--------|------|
| `table` / `pk` | 表名 / 主键列 |
| `writable` | 可写字段白名单 |
| `search` / `filters` | 列表搜索字段 / 等值过滤字段（白名单防注入） |
| `readonly` | 只读模块（所有人不可写） |
| `passwordFields` / `exclude` | bcrypt 字段 / 响应剔除字段（如密码哈希） |
| `enrichUsers` / `enrich` | 按 openid 附加用户信息 / 自定义附加关联字段 |
| `scopeFn` / `readScopeFn` | 写/读数据隔离（如学生只能改自己创建的） |
| `pkGenerator` / `defaults` | 主键生成器 / 新增默认值 |
| `protectSelf` | 自我保护（禁止操作自己的账号） |
| `onAfterCreate/Update/Delete` | 业务事件钩子（fire-and-forget 记时间轴/审计） |

已挂载模块：`users`、`monitors`、`traces`、`sessions`、`file_uploads`、`user_events`、`staff`、`roles`、`menus`、`dict_types`、`dict_items`、`tasks`、`task_collections`、`task_checkins`、`lp_students`、`lp_children`、`lp_family_members`、`subscribe_grants`、`subscribe_sends`、`todo_tasks`、`checkin_reviews`、`seqs`、`staff_events`、`apps`。

### 5.4 审计体系

- **后台 staff 审计（staff_events）**：登录成功/失败、退出、菜单点击（前端上报）、通用 CRUD 增删改查、审核、上传等；记录操作人、IP、UA 指纹、脱敏参数。实现：`staffAudit.js` 的 `logStaffEvent`（fire-and-forget 写库）。
- **用户操作事件（user_events）**：前端 `tracker.js` 埋点（页面访问/菜单点击/按钮点击）→ `/api/analytics/collectEvent`；服务端核心操作（登录/增删改查）由 `events.js` 的 `logEvent` 记录。
- **业务时间轴**：任务/打卡 `task_timeline`（`taskTimeline.js`），fire-and-forget。

### 5.5 后台仪表盘

| 仪表盘 | 路由 | 说明 |
|--------|------|------|
| 监控仪表盘 | `/dashboard/monitor` | 接口链路统计（总量/错误/平均耗时/慢请求）+ 响应趋势 + 监控趋势 + 实例概览 |
| 学习仪表盘 | `/dashboard/learning` | 面向学生的游戏化页：经验/等级、连续打卡连击、成就徽章、任务/打卡统计与趋势、分级提醒文案 |

**学习仪表盘要点**：
- 任务范围：学生按任务派发统计（`task_assignees` 派发给本人 + 本人自建任务），管理员为全员汇总。
- 等级：XP = 有效打卡 ×10 + 完成任务 ×30，等级阈值见 `LEARNING_LEVELS`（10 级封顶）。
- 徽章：累计打卡/连续打卡/任务/等级/科目/活跃/特色系列（40 枚），未解锁显示达成进度。
- 提醒：`buildLearningReminders` 后端生成分级文案（逾期 > 未打卡+进度低 > 未打卡 > 进度低 > 临期 > 全部正常），severity danger/warning/info/success。
- 统计口径：已删除任务的打卡（孤儿打卡）一律剔除。

### 5.6 学习管理（任务系统）

- **任务 `tasks`**：标题/科目(字典)/标签/描述/链接/图片(≤9)/状态(todo|doing|done)/评分 score(0-10)/起止日期/合集/打卡次数/创建人。
- **任务派发 `task_assignees`**：任务 → 多名学生（staff_id）。规则：学生创建/编辑的任务派发**固定为本人**（忽略前端提交，禁止派发给别人）；管理员可按需多选派发。后端 `syncTaskAssignees` 全量替换并校验学生角色员工存在性。
- **任务打卡 `task_checkins`**：图片(≤9，JSON 数组字符串)+备注+日期；任务打卡后 `todo` 自动转 `doing`，打卡次数累加；任务已完成（done）禁止修改/删除打卡。
- **任务合集 `task_collections`**：独立功能（非字典），删除合集先解除其下任务归属（`collection_id` 置 0）避免孤儿引用。
- **任务时间轴 `task_timeline`**：任务/打卡全生命周期事件（创建/更新/完成/删除/打卡/修改打卡/删除打卡），后台「流程」抽屉审计展示。
- **级联删除**：删除任务前先查询关联打卡/图片数（`/api/tasks/deleteStats`）供前端确认弹窗提醒；删除时级联清理任务打卡、物理删除 COS 图片、清理 `file_uploads` 登记、删除派发关联。
- **订阅消息**：`subscribe_grants`（授权）与 `subscribe_sends`（发送记录）支持审核结果/打卡提醒模板；`reminder.js` 定时任务扫描发送提醒。

## 7. 监控与可观测性

### 7.1 系统监控（service_monitor）

- `monitor.js` 每 **10 分钟**采集一次（`startMonitor`）
- 指标：`cpu_cores` / `mem_total_mb` / `instance_spec`（cgroup v1/v2 读取宿主实际限额）+ `heap_used_mb` / `rss_mb` / `cpu_percent` / `uptime_min` / `active_handles` / `active_reqs`
- 同时 `console.log` 打印到云托管日志

### 7.2 接口链路追踪（api_trace）

- **前端**：每次请求生成 UUID（`X-Request-Id` header），回调里测总耗时 `client_cost_ms`，异步上报 `/api/analytics/reportTrace`
- **后端**：`traceMiddleware` 记录 `server_cost_ms` + `start_time`/`end_time` + 脱敏参数 + HTTP 状态 + 客户端指纹
- **合并**：`request_id` 关联，`client_cost_ms - server_cost_ms` = 网络/排队耗时；上报后 `trace_status` 置 `complete`
- **即时入库**：api_trace 为即时单条插入（非批量）——前端在回调后立即上报 reportTrace 做 UPDATE，若批量延迟入库会导致 UPDATE 匹配不到行，永远 server_only

### 7.3 用户画像采集（user_sessions）

- `app.js` 冷启动时调用 `collectSession()`
- 采集：设备信息、网络、电量、启动性能、权限状态、来源场景
- 静默异步上报，失败不感知

## 10. 已知注意事项

1. **`ws` 依赖不可删**：rdb() 运行时动态 require，删除导致全部 DB 失败（AI-SKIP 已标注）。
2. **api_trace 必须即时插入**：前端上报 reportTrace 在回调后立即执行，若走批量延迟入库会匹配不到记录，导致 status 永远 server_only（曾踩坑）。
3. **月份查询**：必须用 `monthRange()` 的 `gte/lt` 范围（TDSQL 精确等值 `= '2026-08-01'` 只匹配 1 号）。
4. **时间格式**：MySQL datetime 列需 `YYYY-MM-DD HH:MM:SS`（用 `nowSql()`），SDK 序列化的 ISO 格式会被拒绝。
5. **tdesign 精简包不入 git**：`miniprogram_npm/` 被 gitignore，重新「构建 npm」会恢复全量。
6. **云函数已全部废除**：原 `lpProxy` 反向代理已删除，课小满改为 `wx.cloud.callContainer` 环境内直调云托管。
7. **后台菜单以数据库为准**：前端菜单从 `/admin/menus` 动态加载，服务端 `requireModulePermission` 按角色-菜单鉴权，菜单可见性与接口权限保持一致。
8. **学生任务派发固定本人**：学生创建/编辑任务派发强制为本人（前后端双重校验），管理员才可多选派发。
9. **tdesign 图标乱码**：课小满的 `postinstall` 脚本 `patch-iconfont.js` 会改写 tdesign 的 `icon.wxss`，只能把 `@font-face` 指向 CDN（`https://tdesign.gtimg.com/icon/.../t.woff`），**严禁删除** `@font-face`——删掉后图标字符（私有区码点 `\E001` 等）无字体可渲染，显示成乱码/方块。手动修改过 `node_modules` / `miniprogram_npm` 后跑 `node scripts/patch-iconfont.js` 即可修复。
10. **存储根路径 `kxm`**：COS 共享根目录为 `kxm`，课小满图片实际存于 `kxm/tasks/...`；存量图片路径从旧前缀迁移需同步执行 UPDATE 语句（见 `sql/upgrade_020_storage_root.sql`）。
