## 1. 概述与设计思想

课小满采用 **三层身份模型**，邀请码是「业务身份」与「小程序用户」之间的准入凭证：

| 层 | 载体 | 说明 |
|----|------|------|
| 1. 登录会话 | `wx.login → openid → LP JWT` | 打开即得，仅含 openid，与微信授权无关 |
| 2. 业务身份 | `t_lp_invites` 邀请码 → 绑定 `openid ↔ staff_id` | 有码能进业务页，无码进身份选择页 |
| 3. 后台账号 | `t_staff`（staff_id / staff_role） | 家长有后台登录能力，学生/家属为占位密码 |

核心约定：

- **邀请码独立维护在 `t_lp_invites`，与 `t_staff` 解耦**，不挂员工表字段。
- **6 位大写**，字符集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（排除易混淆 `0/O/1/I`，共 32 字符，组合约 10 亿）。
- **状态机**：`available（未绑定可用）→ bound（已绑定）` 或 `revoked（已作废，终态）`。
- **一 openid 多身份（共用微信）**：`t_lp_students` 唯一键为 `(app_id, openid, staff_id)`，同一 openid 可绑定家长 + 多个孩子 + 家属；
  业务身份由 token 中的「活动身份 staffId」实时解析，可随时切换。
- **作废即刻生效**：每次业务请求由 `lpAuth` 中间件实时复核该 (openid, staffId) 绑定，配合前端 20s 会话心跳，后台作废/解除后用户最快 20s 内被踢出登录态。

## 2. 数据模型

### 2.1 `t_lp_invites`（邀请码主表）

| 列 | 类型 | 说明 |
|----|------|------|
| invite_id | BIGINT PK | 序列发放 |
| app_id | VARCHAR(32) | 固定 `miniprogram-kxm`（业务表前缀隔离，冗余字段） |
| invite_code | VARCHAR(8) UNIQUE | 6 位大写邀请码 |
| kind | VARCHAR(16) | `student` 学生码 / `parent` 家长码 / `family` 家属共享码 |
| owner_staff_id | BIGINT | 归属账号：学生码=孩子 student 账号；家长码=主家长账号；家属码=主家长账号 |
| child_id | BIGINT | 学生码关联的孩子档案 ID（家长码/家属码为 0） |
| status | VARCHAR(16) | `available` / `bound` / `revoked` |
| bound_openid | VARCHAR(64) | 绑定的小程序 openid |
| bound_staff_id | BIGINT | 绑定后指向的账号（学生码=学生；家长码=主家长；家属码=新建家属账号） |
| bound_at | DATETIME | 绑定时间 |
| created_by | BIGINT | 创建人 staff_id（主家长 / 管理员） |
| created_at / updated_at | DATETIME | 时间戳 |

### 2.2 `t_lp_students`（openid ↔ staff 绑定映射）

- `UNIQUE KEY uk_app_openid_staff(app_id, openid, staff_id)`：**同一 openid 可绑定多个身份（家长/孩子/家属，共用微信）**；同一 (openid, staff) 不重复。
- `bound_status`：1 正常 / 0 已锁定（邀请码作废/解除后锁定，该身份被踢出）。
- `source`：绑定来源标记 `register`（注册建档，家长/个人自建即绑自己手机）/ `invite`（邀请码绑定，孩子自己手机/家属/换绑）/ `auto`（家长自动挂接，建档/一键切孩时自动挂到孩子账号；可安全删除，删后家长再切会自动重建）。
  同一孩子账号可同时存在 `invite`（孩子自己的手机）与 `auto`（家长的手机）两条绑定，互不影响。
- `t_staff.pin_hash`：家长/管理员身份切换 PIN（bcrypt），未设则切换无需校验。

### 2.3 关联表

- `t_lp_children`：孩子档案，`parent_staff_id`（主家长）↔ `student_staff_id`（学生账号），每个孩子一份。
- `t_lp_family_members`：家属关系，`owner_staff_id`（主家长）↔ `member_staff_id`（家属账号）。

## 3. 三类邀请码语义

| 维度 | student 学生码 | parent 家长码 | family 家属共享码 |
|------|---------------|--------------|------------------|
| 谁生成 | 主家长（孩子档案，小程序） | 平台管理员（后台邀请码管理） | 主家长（家属共享页，小程序） |
| 归属账号 | 孩子 student 账号 | 已注册的主家长账号（role=parent） | 主家长账号 |
| 谁绑定 | 孩子本人 | 家长本人（已有后台账号） | 家属本人 |
| 使用次数 | 单次（可用期可重生成） | **单次，绑定即作废** | 单次，绑定即作废 |
| 绑定效果 | openid ↔ 学生账号 | openid ↔ 已有主家长账号 | 自动建家属账号 + 写家属关系 |
| 重生成 | 主家长可自助 | 仅管理员（后台重新生成） | 主家长重新生成新码 |
| 作废 | 家长 / 管理员 | 管理员（并锁定访问） | 家长 / 管理员（并解绑家属） |

### 家长入驻两种模式（关键）

1. **模式 A：无码自动建号** — 家长在小程序「我是家长 → 创建新账号」→ `registerParent`：
   自动创建 `role=parent` 的 `t_staff`、自动绑定当前 openid、生成一张家属共享码、下发后台登录账号（明文密码仅一次）。
2. **模式 B：后台有码只绑定** — 管理员在后台先创建主家长账号（角色=主家长），再生成家长码；
   家长在小程序「我是家长 → 绑定已有账号」输入码绑定，**不会重复建号**，避免「后台一个账号、小程序一个账号」的双账号问题。

> 说明：`registerParent` 已做幂等——若当前 openid 已绑定且身份是主家长，重复调用直接返回当前状态，不重复建号。

## 4. 后端核心逻辑审计

### 4.1 生成（`lpAuth.createInvite` / `genUniqueInviteCode`）

```text
genUniqueInviteCode → 生成 6 位码 → 查 t_lp_invites 去重（最多重试 10 次）→ nextSeq 发 invite_id → insert
```

- 创建方统一为 `createInvite({ kind, ownerStaffId, childId, createdBy })`，三处调用：
  - `family.js`：新增孩子档案（student）、重生成学生码（student）、生成家属共享码（family）。
  - `admin.js`：`lp_invites` CRUD 创建（student/parent/family）、`regenerate` 重新生成（student/parent）。
  - `registerParent`：为新建主家长生成家属共享码（family）。

### 4.2 查询（`findBindableInvite`）

- 入参：`trim().toUpperCase()`，正则 `^[A-Z0-9]{6}$` 校验。
- 命中条件：`kind ∈ {student,parent,family} && status === 'available'`。
- **不校验归属账号有效性**，由各绑定分支在拿到邀请码后二次校验（owner 存在 + 角色正确 + 状态启用）。

### 4.3 绑定（`POST /api/lp/bind`，三分支）

统一前置：
- `verifySession`（LP JWT → openid）；无 token 时回退 `loginCode` 换 openid。
- 账号级锁定（`t_users.locked_until`）→ 423。
- **限流**：同一 openid 15 分钟最多 10 次尝试（进程内滑动窗口）。

| 分支 | 校验 | 效果 |
|------|------|------|
| student | owner 存在且 `role=student` 且启用 | 绑定映射（追加/激活）→ 码置 `bound` |
| parent | owner 存在且 `role=parent` 且启用 | 绑定映射（追加/激活）→ 码置 `bound` |
| family | owner 存在且 `role=parent` 且启用 | 自动建 `role=family` 账号 + 写 `lp_family_members` + 绑定映射（追加）→ 码置 `bound` |

幂等与防换绑：
- 同码重复绑定（网络重试）→ 幂等返回成功。
- 已绑定其他账号（共用微信）→ **追加绑定**：同一 openid 可同时持有家长/孩子/家属多个身份，不再拒绝。
- 家属已是同一主家长家属 → 幂等返回；已是别家家属则新建家属账号追加绑定。

### 4.4 实时鉴权（`lpAuth` 中间件 + 前端心跳）

```
请求 → X-LP-Token(JWT: openid + staffId) → userLockedUntil(锁定403)
     → lp_students(openid + staffId 绑定，bound_status=1)
     → staffById(staff 存在/启用/角色白名单) → familyScope(家庭可见范围) → req.lp
```

- 绑定解除（`bound_status=0`）或账号不可用 → `401`，前端清态回身份页（非锁定态）。
- 账号被锁定 → `403`，前端进锁定页展示原因/解封时间。
- 前端 `app.js` 启动 `startSessionGuard`，20s 心跳轮询 `/api/lp/session`，收到 401/403 即清态跳转。
- **身份切换**：`POST /api/lp/switch`（`{ staffId, pin? }`）校验目标为本 openid 有效绑定 → 签发新 token；
  切到家长/管理员身份若已设 `pin_hash` 必须携带正确 PIN（防孩子越权切家长模式）。

### 4.5 作废 / 解除 / 重新生成

| 动作 | 入口 | 行为 |
|------|------|------|
| 后台删除邀请码 | admin `onBeforeDelete` | 删除；已绑定的学生码/家长码同步 `lp_students.bound_status=0` 锁定访问 |
| 后台作废 | `POST /api/lp_invites/revoke` | 码置 `revoked`；已绑定学生码/家长码锁定访问 |
| 后台重新生成 | `POST /api/lp_invites/regenerate` | 作废该账号可用码 → 发新码 → **恢复 owner 名下访问**（`bound_status=1`） |
| 家长重生成学生码 | `family/children/invite` | 作废该孩子 available 码 → 发新码 |
| 家长作废学生码 | `family/children/invite/revoke` | 作废该孩子全部学生码（含 bound） |
| 家长作废共享码 | `family/share/revoke` | 码置 `revoked`；已绑定家属 → 解除家属关系 + 锁定访问 |
| 删除孩子档案 | `family/children/delete` | 软删档案 + 作废 available 码 + 禁用学生账号 |
| 删除/停用员工 | admin `cleanupStaffLpData` | 作废其名下 available 码 + 作废绑定到它的 bound 码 |

### 4.6 后台管理（`/api/lp_invites`，仅管理员）

- CRUD 由通用引擎 `crudRouter` 驱动，`writable: [kind, owner_staff_id, child_id, status]`。
- `onBeforeCreate`：类型白名单 + 归属账号校验（学生码=学生；家长码/家属码=主家长，且状态启用）+ 自动生成邀请码 + 默认 `available`。
- `onBeforeUpdate`：禁止手动置 `bound`；改类型/归属账号时复校验角色匹配。
- `enrich`：附归属人昵称、绑定人昵称、关联孩子名、绑定小程序用户昵称。
- **后台不提供「新增绑定」**：openid↔staff 绑定由小程序输码自动完成（`/api/lp/bind`）；
  为已有 staff 账号开通小程序访问 = 在「邀请码管理」新增一条归属该账号的邀请码并下发用户。

## 6. 安全审计

| 项 | 现状 | 结论 |
|----|------|------|
| 邀请码熵 | 32^6 ≈ 10 亿，字符集排除易混淆 | 足够，属弱共享密钥 |
| 爆破防护 | `/api/lp/bind` 同一 openid 15 分钟 10 次限流 | 有；进程内 Map，多实例可绕过 |
| 单次使用 | 绑定即置 `bound`；`findBindableInvite` 仅放行 `available` | 有 |
| 越权防护 | 家长/家属生成码时 `childOwned` 校验归属；管理员专用接口校验 `role=admin`；后台非管理员 scopeFn 限本人 | 有 |
| 归属校验 | 绑定分支二次校验 owner 角色+状态 | 有 |
| 实时踢出 | lpAuth 中间件每请求复核 + 前端 20s 心跳 | 有 |
| 密码 | 后台账号明文密码仅创建/重置时下发一次，bcrypt 存储 | 有 |
| 审计 | 后台增删改/作废/重生成写 `staff_events`；小程序关键操作写 `user_events` | 有 |

## 8. 关键流程

### 8.1 学生入驻（主家长发起）

```
家长新增孩子档案 → createLpAccount(role=student) + lp_children + 生成学生码
孩子小程序「我是学生」输入码 → /api/lp/bind(student 分支) → 绑定映射 + 码置 bound
孩子业务请求 → lpAuth 实时鉴权（staff 启用 + bound_status=1）
```

### 8.2 家长入驻（模式 A 自动建号 / 模式 B 后台发码）

```
模式A：小程序「我是家长→创建新账号」→ registerParent → 建 parent 账号 + 绑定 + 发家属共享码 + 下发后台账号
模式B：管理员后台「管理员管理」建主家长账号 + 「邀请码管理」生成家长码
      → 家长小程序「我是家长→绑定已有账号」输码 → /api/lp/bind(parent 分支) → 绑定映射 + 码置 bound
```

### 8.3 家属入驻（与孩子同一张「我有邀请码」卡片）

身份选择页仅展示「我是家长 / 我是个人 / 我有邀请码」三张卡片：孩子与家属逻辑完全一致
（都是输入 6 位邀请码），合并为一张「我有邀请码」，由后端按邀请码 kind 自动识别
学生码 / 家长码 / 家属共享码。

```
主家长「家属共享」生成码 → 家属小程序「我有邀请码」输码 → /api/lp/bind(family 分支)
→ 建 family 账号 + 写 lp_family_members + 绑定映射 + 码置 bound
```

### 8.5 共用微信多身份切换（家长 + 孩子一台手机）

```
1. 家长注册/绑定家长身份（registerParent / 家长码）→ 生成孩子学生码
2. 家长在同一手机输入孩子学生码 → bind(student 分支) → 追加绑定（openid 同时持有 parent + student）
3. 「我的」页身份切换 → /api/lp/switch(staffId)
     ├─ 切到孩子：无需 PIN，直接签发新 token
     └─ 切到家长：若已设 PIN → 必须输入正确 PIN，否则 403
4. 家长在设置页「身份保护」开启 PIN → t_staff.pin_hash（bcrypt，4-6 位数字）
5. 绑定形成多身份且家长未设 PIN → 绑定完成页/我的页提示风险，家长自选是否开启
```

### 8.5.1 家长一键切到孩子身份（各有手机也能用，不影响孩子账号）

```
1. 家长/管理员在「孩子档案」点「以孩子身份进入」→ POST /api/lp/switchChild({ staffId })
2. 后端校验目标为本人名下孩子（parent）或任意学生（admin）→ 若未绑定则自动把该孩子账号
   绑定到当前 openid（activateBinding，幂等，不消耗学生邀请码）→ 签发孩子身份 token
3. 前端 persistLogin + reLaunch 首页 → 家长以孩子身份操作（打卡/完成任务等）
4. 孩子在其它手机绑定的账号完全不受影响：lp_students 按 (app_id, openid, staff_id) 独立成行，
   parent 侧新增行不触碰 child 侧行；切回家长身份走 /api/lp/switch（已设 PIN 则需校验）
5. 新建孩子档案时后端自动执行同样绑定（family.js autoBindChild），新孩子即刻出现在身份列表
```

### 8.6 作废 → 踢出链路

```
后台作废/删除/解除 / 家长作废共享码
→ 码置 revoked / lp_students.bound_status=0
→ 前端 20s 心跳或下次请求收到 401 → 清 token/staff/role/后台凭据 → reLaunch 身份页重新绑定
```

## 9. 结论

邀请码机制整体设计清晰：独立表维护、状态机简单、单次使用 + 实时复核 + 前端心跳保证了「作废即失效」，
三类码覆盖学生/家长/家属准入，权限校验与越权防护到位。

主要风险集中在：**绑定并发竞态（#2）**、**后台绑定管理角色白名单不覆盖家长/家属（#1）**、
以及**作废路径语义不一致（#4/#7）**。上述三项已在本次审计后修复（见 §10），
剩余 #3（多实例限流）与 #10（家长自助重生成家长码）为架构/产品级待办。
